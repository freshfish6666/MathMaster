# N祭坛

注册ID为 `mathmaster:n_altar`。蓝青石像占1×1×2，上半托几何体、下半正面ℕ与少量触须；朝向放置者。无需下方支撑，仍须留出上方空间。破坏任一半清理整座，生存仅掉落一个祭坛，创造不掉落，活塞不可移动。当前加入创造方块页；无配方，随N类试炼生成，定位为在遗迹获得、可挖走。

## 正常与血祭

下半正下方为灵虚块时自动进入血祭，无需右击启动；其他方块或空气时为正常模式。正常模式ℕ青色且不发光，支持下述求知、合意与亵渎献祭。血祭ℕ红色且仅符文满亮度，下半持续提供7级普通方块照明。原版方块光没有颜色，蓝紫视觉通过粒子表现，不声称真实彩色光源。

## 正常献祭的永久解锁

玩家有效IQ大于50，且已成功洞悉至少5种不同生物后，永久解锁全部正常献祭。两项条件需同时达成；使用已有洞悉记录，每种生物仅计一次，答错、未完成或自我洞悉不增加种类数。有效IQ包括心流和学士帽加成，不使用血祭的附近玩家平均值。

达到条件时向本人提示解锁；死亡、重连、跨维度、摘下装备或IQ下降均不撤销。状态保存在玩家已有洞悉记录的新增 `n_altar_unlocked` 布尔键中，随原记录死亡复制；旧存档缺少该键时默认未解锁，保留既有洞悉种类，满足条件后自动解锁。此状态不增加网络字段或包。

尚未解锁时，右击正常祭坛显示当前有效IQ与洞悉种类进度，并提示“手持智识之镜，对部分生物按住右键进行洞悉”。指定祭品均不消耗、不启动冷却、不抽随机、不增加经验或污染。空手右击也可查看提示；旁观/死亡玩家不参与。血祭自动启动与奖励开箱不要求解锁。

## 求知献祭与神谕

正常模式下，手持指定物品右击祭坛上半或下半即可献祭，主副手均支持。每次接受一件，成功或失败都消耗一件；创造模式也按同一献祭规则消耗。判定、扣除和聊天回应仅由服务端执行，不广播给其他玩家。不增加污染、冷却、玩家收集进度或物品奖励。血祭模式、旁观玩家、空手及其他物品不参与求知献祭，不消耗祭品。未知物品仍遵循原版物品交互。

| 祭品 | 神谕成功概率 |
|---|---:|
| 铁锭 | 30% |
| 金锭 | 50% |
| 绿宝石 | 70% |
| 钻石 | 90% |

物品仅决定成功概率，祭坛决定抽取池。神谕在独立 `oracle/` 模块中分为 `low`（低级）、`medium`（中级）、`high`（高级），N祭坛始终使用低级池。成功后从池内等概率抽取一条并在聊天显示，允许重复；失败显示“祈求未获回应”。低级池为空时提示暂不可得且不收取祭品，避免错误的数据包造成无内容消耗。

当前低级池为用户提供的 `MathMaster-resource/Oracle/low.txt` 中17条神谕，每个非空行对应一条，标点与正文原样保留；原三条已全部移除。

合集位于 `data/mathmaster/oracles/low.json`；中、高级合集预留为空。修改合集后重新启动或执行 `/reload` 生效。每条使用稳定且全局唯一的资源ID，追加新信息不改变既有ID。可直接在原合集的 `entries` 数组中追加，也可由数据包提供不同路径的合集文件，所有相同 `tier` 的有效合集共同组成一个池。例如 `data/example/oracles/extra.json`：

```json
{
  "tier": "low",
  "entries": [
    { "id": "example:low/new_message", "text": "这里填写新的神谕正文。" }
  ]
}
```

每条 `id` 必须为合法资源ID，`text` 为非空字符串。文件按资源ID排序加载；重复条目ID只保留第一次，避免重复文件改变抽取权重。一个合集含非法字段时跳过整份合集并记录日志，其余有效合集正常加载。重载建立全新只读快照，已删除条目不会留在新池中。

正文默认使用 `text`，因此新增神谕无需另写语言键；可选语言键由ID生成，如 `example:low/new_message` 对应 `oracle.example.low.new_message`。语言文件存在该键时优先显示对应翻译，修改已有正文时需同步已有语言键。当前内置条目直接使用用户中文正文，没有新增翻译；旧三条语言键已移除。

## 合意之物

正常模式下手持考拉兹果实或素数核心右击任一半，主副手均支持，服务端执行且仅向献祭者回应；创造模式也消耗祭品。旁观、死亡及血祭模式不接受。各类冷却按玩家计算，切换祭坛、维度或重连不能绕过；仅存于本次服务器运行，重启清空，不添加存档字段。果实、指引、亵渎三类冷却互不影响，求知献祭仍无冷却。

| 祭品 | 效果 | 成功消耗 | 冷却 |
|---|---|---:|---:|
| 考拉兹果实 | 智识经验+20，数字化污染值+3 | 1 | 5秒 |
| 素数核心 | 指引最近的未完成主世界传送门X/Z坐标 | 1 | 60秒 |

果实遵循既有基础智识200上限，接近上限时经验截断；已达上限不消耗、不增加污染、不启动冷却。污染直接增加数值，不施加持续污染效果；沿用单位元护盾抵消与污染满100致死/归零机制，奖励不因护盾抵消污染而撤销。

素数核心仅在主世界可用，以发起玩家的位置为中心按水平距离查找4096格内普通或巨型未完成主世界传送门，已探索遗迹仍可被指引。距离按原版结构定位点计算，返回聊天坐标，不传送、不改变结构引用次数。搜索逐tick推进，全服务器同时至多请求一个候选区块的STRUCTURE_STARTS阶段，可能加载或生成结构起点，但不直接同步等待或生成完整地形。搜索时提示“祂的目光正在远方寻觅……”。找到才扣除物品并开始冷却，未找到、非主世界、冷却中或重复请求不消耗。搜索最多等待60秒；换维度、换掉手中祭品、死亡、离线、原祭坛被拆或改为血祭时取消，不收费。

## 亵渎之物

萤石方块（不是萤石粉）、空集、海晶灯、三猫奶粉属于亵渎之物。正常模式右击消耗一件，必定从下表抽取一种惩罚，并提示“祂看见了你的献礼，却不悦纳。”四种祭品共用玩家10秒冷却。

| 惩罚 | 概率 | 数值 |
|---|---:|---|
| 雷击 | 20% | 一次6点基础雷击伤害，按既有伤害规则结算；视觉雷电不点火、不连击、不伤旁人 |
| 失明 | 25% | 失明Ⅰ，10秒 |
| 缓慢 | 25% | 缓慢Ⅱ，10秒 |
| 虚弱 | 20% | 虚弱Ⅰ，10秒 |
| 污染 | 10% | 数字化污染值直接+8 |

新施加的状态效果均不超过10秒，不削弱或缩短已有更强/更久效果；污染保留既有单位元护盾及满100致死规则。未知物品继续走原版交互，不视作亵渎。中高级祭坛未接入；N类试炼已含祭坛。既有血祭计数、箱子、音乐及祭坛存档字段保持不变；玩家解锁状态单独保存。

## 血祭规则

血祭以祭坛下半中心为圆心，生物效果和死亡贡献范围仍为三维半径10格（包含边界）。每20 tick错峰刷新一次，根据同维度三维12格内存活的生存/冒险玩家平均有效IQ选择效果：

| 平均有效IQ | 目标效果 |
|---|---|
| 小于50 | 力量Ⅰ、速度Ⅰ |
| 50～100（含两端） | 速度Ⅰ |
| 大于100且小于160 | 缓慢Ⅰ |
| 160及以上 | 缓慢Ⅰ、虚弱Ⅰ |

计入心流和学士帽加成，平均值保留小数；创造、旁观和死亡玩家不计，12格边界计入。范围内无符合条件玩家时按IQ 0处理。只向原版Enemy敌对Mob及 `mathmaster:n_altar_targets` 标签生物施加效果，标签默认包含数字5/6/7/8/9；一般被动生物和玩家不受影响。每次效果持续25 tick，按原版合并保留更强或更久的外部效果，不改基础属性。切档后旧效果自然到期，常规刷新下最多短暂重叠5 tick；离开或结束血祭后祭坛短效果最多保留1.25秒，不主动清除外部药水效果。

范围内上述目标的真实死亡计为一次献祭，死亡来源不限。LivingDeathEvent之后在本维度Post tick确认实际死亡，取消死亡不计；同一UUID在本轮最多计一次。多个祭坛范围重叠时只计给最近的血祭祭坛，等距以坐标稳定裁决。只查询已加载祭坛，不强制加载区块。

每成功献祭一次产生蓝色灵魂火粒子与逐渐稀疏的紫色粒子，下半亮度由15在约40 tick（2秒）内降回基础亮度。密集献祭重启脉冲计时。ℕ在血祭期间仍为红色；奖励完成后恢复正常青色，最后一次脉冲继续消散。

默认20次将下方灵虚块直接转为名为“N类奖励”的原版单箱，祭坛保留并退出血祭。奖励只生成一次，额外死亡不重建或重抽该箱。之后重新放置灵虚块可开启新一轮；移走底座或切回正常模式会清空未完成进度。进度、当前血祭轮次和本轮已计死亡UUID保存在下半方块实体，卸载/重启可恢复；临时光效不保存。旧版已放置的无方块实体祭坛，在区块加载后Post tick补齐控制器；仅遍历含祭坛的区块区段，不强制加载。

服务端配置 `n_altar.required_offerings` 默认20，允许1～4096；只调整完成门槛。两种半径、IQ分档和脉冲当前固定。

## N类遗迹补给

遗迹自带箱子使用独立战利品表 `mathmaster:chests/n_altar_ruins`，每箱独立抽取4～6次，允许重复、无保底；共24项，总权重239。常见/一般/稀有/超级稀有的每件权重分别为30/10/3/1，使用独立随机序列mathmaster:chests/n_altar_ruins。血祭奖励仍使用 `mathmaster:n/blood_sacrifice`，两者独立；补给箱不需要完成血祭。

```mcfunction
/setblock ~ ~ ~ minecraft:chest{LootTable:"mathmaster:chests/n_altar_ruins",CustomName:'{"text":"N类遗迹补给"}'}
```

替换为实际坐标放置，保存结构模板前不要开箱；开箱会抽取战利品并清除LootTable引用。客户端重启加载新资源后可测试；已打开的测试箱需重新放置。N类试炼模板中的6个补给箱已引用此表，整座共抽取24～36次；另3个空箱保留。更新资源并重载后，尚未打开且保留LootTable引用的箱子使用新表，已打开的库存不刷新。

## 遗迹试炼刷怪笼

遗迹方案为四个原版试炼刷怪笼：僵尸、骷髅、数字9、数字8各5只，每组同时最多1只；多人不增加数量，关闭刷怪笼完成奖励，保留怪物自身掉落与祭坛奖励箱。接受皮亚诺等额外生成怪物对血祭的贡献。数字8/9的试炼生成跳过低光照与皮亚诺装备门槛，主世界/非和平限制及自然生成规则保留。领取指令、布局、干净模板保存与旧配置调整见 [放置说明](n-altar-trial-spawners.md)。刷怪笼与祭坛独立启动/冷却，不增加战斗室控制器。

## 血祭音乐

使用用户选定的 `N_Song_1.wav`，全长144.08秒（2分24秒）。原文件不改动，逐字节副本和转换报告保存在 `dev-assets/n-altar/music/approved`；30秒原创合成试听与MIDI仍保留在draft-01。正式声音仅使用48kHz双声道Vorbis OGG，设置stream流式解码，不把原WAV或开发资料放入游戏资源。

- 活跃血祭祭坛下半中心三维10格内播放完整歌曲，播完从头重播。进入和离开范围均用1.5秒线性音量渐变；在离开淡出结束前返回，继续当前进度，完全静音后再返回则从头播放。
- 祭坛被移除、灵虚块转奖励箱或其他使血祭模式结束的已加载方块变化，会进入尾声。当前曲进度已达128秒时，沿当前歌曲自然播完；否则以2秒交叉淡化接入128秒起的16.08秒曲尾，等待新流真正启动后才淡出旧流，尾声不循环。
- 尾声也受原祭坛位置10格范围和渐变限制；尾声途中出现活跃血祭，则交叉淡化回完整歌曲。同一客户端范围重叠只播放一份音乐，按最近祭坛确定来源；还有其他活跃祭坛在范围内时继续血祭音乐，不因其中一座结束而进入尾声。
- 遵守原版主音量与“音乐”滑块，保持立体声；播放期间通过SelectMusicEvent暂停原版情境BGM调度，结束后恢复。跨维度、断线、玩家死亡或静音立即清理。单人暂停冻结进度；资源重载中声音被停止后，仍在活跃范围内则重新开始歌曲。区块卸载本身只按离开处理，不误判为血祭完成。
- 客户端每10 tick查询至多九个已加载区块的方块实体，每刻复核少量候选状态，识别结束与范围变化；不扫描整个10格立方体、不强制加载区块、不增加网络负载或存档字段。接近曲尾的进度采用音频流启动后、不含单人暂停的本地播放计时，按客户端刻更新，存在少量启动计时偏差。

新增声音ID `mathmaster:music.n_altar.blood_sacrifice`、`mathmaster:music.n_altar.outro`；生产资源为 `sounds/music/n_altar/blood_sacrifice.ogg` 与 `blood_sacrifice_outro.ogg`。时序规则集中在NAltarMusicSequence，转换脚本中OUTRO_START与其128秒常量需同步调整。整曲重复保留原作尾部自然衰减，不宣称无缝的音乐段落循环。客户端循环衔接、曲尾选择和交叉淡化听感需实机试听。
